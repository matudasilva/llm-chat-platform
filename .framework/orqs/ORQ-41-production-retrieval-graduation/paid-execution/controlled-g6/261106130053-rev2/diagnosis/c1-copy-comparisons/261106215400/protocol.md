# Direct old/new C1 receipt-copy comparison

Prospective diagnostic, not a G6 gate. Operator authorized following the direct same-test old/new C1 recommendation. Forty local ASGI requests total: 32 measured and eight warmups. Both arms are full C1: Capture, application/SDK attempt tracking, invocation lifecycle and candidate_evidence validation all remain active in both images. No C0 image or lightweight baseline tape arm is used. Internal cache suffixes c0/c1 are only distinct namespace slots required by the existing Redis wrapper; they do not select application semantics.

Old image is the immutable parent C1 (7417a2...), new image is the reviewed one-file overlay (4e68cc...). Source-inventory proof binds the only change to context_evidence.py. Same inherited runtime dependencies, configuration semantics, model, resources (2 CPU/2 GiB), local PostgreSQL image, capture/observer behavior and stub responses. New paired conversation/request IDs, fresh disposable DBs with identical P3/history content. Neither previous conversation state nor cached response is reused.

Four language/path cells (EN/ES x JSON/SSE). Each arm/cell uses one document warmup and one measured case of each document/history/combined/empty shape. Both images process identical paired queries/history in separate DBs. Serial workers; fixed arm order old-new for EN JSON and ES SSE, new-old for EN SSE and ES JSON. Each image goes first once per language and once per protocol. The order is counterbalanced across cells, not randomized within pairs. It does not remove every time/order/cell interaction. There is one prospective attempt, no best-run selection and no automatic resends.

Measurements preserve the aggregate worker boundaries: wall then process CPU at ASGI ingress; process CPU then wall at native-send entry. Only primary timestamps settle the preparation interval. Rewrite capture remains included; primary Capture processing and response/final validation remain after the timestamp. No per-function, SQL, logging or SDK timing wrappers. Process CPU includes all threads/background work. CPU/wall cannot be subtracted to infer waits; no full-response latency or live model TTFT is measured.

Analysis fixed before execution: compare all 16 measured matched sample IDs using new-minus-old CPU and elapsed wall deltas. Report each pair, median and full range by category and language/path, negative/zero/positive counts, and order strata. Negative delta favors the optimization. Retain warmups separately. Report payload hash/call-purpose parity, 40 unique valid candidate contexts and PostgreSQL final exact contents. No threshold or PASS is invented for performance; functional/evidence correctness remains mandatory. Four pairs per category cannot certify a small improvement or a G6 p95 margin.

If differences are mixed or small relative to sample spread, conclude that benefit is unproven at request level and do not justify a formal N100 rerun from this diagnostic alone. A consistent measured reduction can justify considering the formal gate, but cannot establish that its +5% criterion passes. The copy microbenchmark suggested only about0.22ms for three copies, much smaller than the historical multi-ms gap; this test can be inconclusive even if the microbenchmark is correct. Do not subtract any estimated cost from historical p95, disable observers or change thresholds to pass.

P2 only: no external credentials or dotenv, network-none PostgreSQL namespace/no published ports, local native generation/embedding/reranker stubs, P2 socket guard and empty external-network audit. No paid campaign/provider call, runtime/P5/model/threshold/DB schema change, Notion or commits. New controller/worker modules and tests are isolated outside app/. Source and fixture pins are immutable on admission. A fresh independent exact-plan review receipt is required; existing execution barriers cannot be reused or reset.
