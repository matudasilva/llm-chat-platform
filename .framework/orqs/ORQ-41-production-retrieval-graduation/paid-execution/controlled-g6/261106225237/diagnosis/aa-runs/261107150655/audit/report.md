## Confirmed finding AA-AUDIT-R1 — MEDIUM

The performance worker does not release completed request contexts as intended. `local_api.py:25` retains every request-owned Task; `track_tasks` adds them at line63, while `quiesce` checks completion/session closure without pruning them. `aa_calibration_worker.py:90` clears only capture.bodies, capture.sends and lifecycle.evidence_states. Completed tasks remain roots for their Context, including context_evidence._current. Requests, sessions and closed_sessions also accumulate for the lifetime of the worker. The original controlled_latency_worker.py:90 has the same incomplete release pattern.

Reproduction: run audit/probe_retention.py in the exact immutable C1 image with the frozen local_api.py, P2/network-none and no API/SQL/provider calls. After each of eight serial logical iterations, successful quiescence and the worker-style evidence_states.clear(), the cleared list has length0 but the task set retains1 through8 completed tasks, and weak references prove1 through8 Evidence objects remain alive. Each completed task's actual Context contains the corresponding Evidence. Releasing only those completed-task references in this isolated probe allows all eight Evidence objects to be collected. `gc.collect` is used solely in this reachability reproduction, never as a proposed request/benchmark modification.

Impact: the measurement process carries prior request state and grows its tracked heap through the cell. It also scans cumulative session/task collections during post-request quiescence. The scan is outside the timing interval, but retained objects and allocations can influence later measured requests. This is harness retention, not proof of a production memory leak or a causal percentage of the p95 failure. The observed timing trends are not uniformly monotonic, so the audit does not claim that retention explains every outlier or all A/A failures.

Smallest proposed remediation: a performance-harness-only release operation after response completion, quiescence, full C1/transport validation and durable row projection. Require all owned tasks done, all sessions closed/no transactions and no unresolved ownership; then release the completed-task, validated request/event and closed-session references and existing capture/state lists. Preserve required raw/immutable receipts and fault evidence. Refuse unsafe release; never cancel in-flight work, suppress late evidence, force GC, move the timing endpoint or change application behavior. Prefer an isolated helper called by the A/A worker, preserving the shared Lifecycle implementation used by G1/G2/G3/G9. The same issue must be addressed prospectively in any future formal performance worker before requalification, with its own reviewed pins.

Required regressions: weak-reference release across repeated completed cases; no request-count growth of tracking collections after release; refusal with a pending task, active transaction or unclosed session; full C1/serialized-body/row equivalence; JSON/SSE finalizer/cancellation ownership; retained error/late-observer evidence; unchanged ingress/native-send boundary. Independently review the exact fix before one new frozen A/A execution. Do not silently reinterpret the previous FAIL or repeat the old packet until favorable. No fix or new measurement is authorized by this audit report.
